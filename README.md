# WukongBench

Консольный Windows-инструмент на **C# / .NET 8** для последовательного CPU- и GPU-прогона **Black Myth: Wukong Benchmark Tool**, Steam AppId `3132990`.

Утилита ищет Steam в реестре, читает дополнительные библиотеки, резервирует конфигурацию, применяет два профиля, проходит меню, ожидает результат каждого теста, собирает характеристики компьютера и записывает отчёт. Результаты не симулируются. Отсутствующие измерения не заменяются нулями или синтетическими оценками Unreal Engine.

**Статус проверки:** проект собран .NET SDK 8.0.425 на macOS; тесты независимой логики выполняются на macOS. На этой машине нет Windows и установленного Benchmark Tool. Полный прогон, взаимодействие с OCR и соответствие адаптера текущей версии приложения здесь **не проверены**. Это существенное ограничение: успешная сборка не подтверждает работоспособность сквозного сценария. Источники и спорные детали перечислены в [docs/RESEARCH.md](docs/RESEARCH.md).

## Требования

- Windows 10 2004 (build 19041) или Windows 11, x64; для обычной сборки — .NET 8 Desktop Runtime.
- Установленный через Steam **Benchmark Tool**, а не основная игра. Steam должен быть авторизован; остановленный клиент программа попробует запустить.
- DirectX 12 и подходящий видеодрайвер. Программа использует DX12 для обоих профилей.
- Активный, разблокированный рабочий стол. Программа работает с окном, поэтому во время прогона нельзя переключать приложения, пользоваться мышью, блокировать экран или оставлять поверх игры оверлей. RDP и фоновые службы не поддерживаются.
- Установленный английский компонент **Windows OCR**. Проверка выполняется до изменения конфигурации. Язык приложения временно переключается на английский. При отсутствии OCR добавьте компонент английского языка в настройках Windows; при необходимости администратор может использовать `Add-WindowsCapability -Online -Name Language.OCR~~~en-US~0.0.1.0`.
- Права записи в каталог конфигурации Benchmark Tool. Утилита и игра должны работать с одинаковым уровнем прав. Автоматического повышения прав нет.
- Игра и её Benchmark Tool должны быть закрыты до запуска. Не запускайте другие их экземпляры во время измерений.

## Сборка

В корне репозитория:

```powershell
dotnet build WukongBench.sln -c Release
dotnet run --project tests/WukongBench.Tests -c Release
```

Тестовый проект — небольшой исполняемый набор проверок с ненулевым кодом выхода при ошибке; сторонний test runner не нужен. Он проверяет VDF, INI, восстановление, повреждение backup, свежесть и полноту результатов. Фикстуры парсера существуют только в тестовом проекте и не попадают в отчёты программы.

Для сборки EXE со встроенным runtime:

```powershell
dotnet publish src/WukongBench -c Release -r win-x64 --self-contained true -o artifacts/win-x64
```

Для переносимой сборки скопируйте **весь** каталог `artifacts/win-x64`. При восстановлении пакетов требуется доступ к NuGet: Windows Desktop и Windows SDK reference packs нужны также при сборке на macOS/Linux. `EnableWindowsTargeting` включён; запустить Windows-часть на macOS/Linux нельзя.

## Запуск

```powershell
dotnet run --project src/WukongBench -c Release
# Или опубликованная версия:
.\artifacts\win-x64\WukongBench.exe
```

Дополнительные параметры:

```powershell
WukongBench.exe --output .\reports --timeout-minutes 30
WukongBench.exe --recover-only
WukongBench.exe --help
```

По умолчанию на каждый запуск приложения, включая первый запуск для создания конфига, выделяется 20 минут. Настройки первого запуска создаёт само приложение: утилита ожидает главное меню и закрывает его перед применением CPU-профиля. Если появляется неизвестный экран первого запуска, работа завершается по тайм-ауту с диагностикой.

Основной сценарий не запрашивает подтверждений. `Ctrl+C` отменяет работу, останавливает запущенные процессы и восстанавливает конфигурацию. Коды выхода: `0` — оба теста и восстановление успешны (либо успешен `--recover-only`), `1` — ошибка, `2` — ошибка восстановления, `130` — отмена.

## Профили

| Параметр | CPU | GPU |
|---|---|---|
| Выходное разрешение | 1280×720, окно | Нативное разрешение основного экрана, окно без рамки |
| Render scale | 50%, целевой рендер около 640×360 | 100% |
| Качество | Low, UI level 1 / scalability 0 | Cinematic, UI level 5 / scalability 4 |
| RT | OFF | ON, level 2, если выбранный адаптер подтверждает DXR |
| Frame Generation | OFF | OFF |
| VSync / FPS limit | OFF / OFF | OFF / OFF |
| Dynamic resolution / Motion Blur | OFF / OFF | OFF / OFF |

Профили зафиксированы в `BenchmarkProfile`, отображение на игровые поля — в `BenchmarkConfigManager`. Выбирается аппаратный DXGI-адаптер с наибольшей выделенной VRAM; его индекс передаётся движку. Поддержка RT проверяется через `D3D12_FEATURE_D3D12_OPTIONS5`, а не по названию GPU. Если проверка недоступна, RT отключается с примечанием в отчёте. Максимальное качество RT разных версий не предполагается: используется известное значение `RtxLevel=2`.

CPU-профиль уменьшает нагрузку GPU, но не превращает игровую сцену в чистый CPU-тест: результат всё равно зависит от GPU, драйвера и сцены. GPU-профиль использует нативное разрешение, чтобы не требовать поддержки виртуального 4K; на 1080p-мониторе это 1920×1080, на 4K — 3840×2160. На экранах меньшего разрешения нагрузка будет ниже. Для сопоставимых GPU-прогонов используйте одинаковое разрешение монитора. Никакой гарантии достижения конкретного bottleneck программа не выдаёт.

В конфиге изменяются как `UISettingData`, так и группы Unreal, плюс Engine.ini для отключения ограничителей. Высота внутреннего рендера в INI и процент `ImageQuality` в JSON — разные представления. Индекс `ScreenResolution` в игровом UI не угадывается: используются размеры окна в INI и аргументы движка. Если приложение их переопределит, проверка результата должна отклонить прогон.

## Автоматизация и достоверность

1. `SteamLocator` читает HKCU/HKLM в 32-/64-битном представлении, затем `libraryfolders.vdf` и `appmanifest_3132990.acf`. Путь установки берётся из manifest. В коде нет пути к Steam конкретного компьютера.
2. `ApplicationInspector` сохраняет список найденных конфигов, логов и истории и Steam build ID. Это позволяет исследовать конкретную установленную версию, не предполагая единственный путь результатов.
3. `BenchmarkUiDriver` распознаёт английские кнопки Windows OCR, нажимает `Benchmark`, затем `Confirm`. Проверяется активное окно и принадлежность точки клика. Во время подтверждённого теста ввод прекращается.
4. `ResultHistoryWatcher` проверяет `b1/BenchMarkHistory/Tool` и `b1/Saved/BenchMarkHistory/Tool` относительно `%TEMP%`, `%LOCALAPPDATA%` и каталога установки. Файлы без расширения также поддерживаются. Старые хэши исключаются, новый файл должен стабилизироваться между двумя опросами и содержать полный JSON с согласованными FPS и непустым `Records`.
5. `BenchmarkResultParser` требует `FPSAvg`, `FPSMin`, `FPSMax`; `FPS95` сохраняется под исходным именем без переименования в 1% low или пересчёта методики. Файл копируется целиком как доказательство происхождения результата.
6. Разрешение, качество, масштаб, FG и RT сравниваются с полями истории. Если поле отсутствует или отличается, прогон получает статус `Failed`; полученные FPS сохраняются для диагностики. VSync/FPS limit и драйверные лимиты история не подтверждает — это явно отмечается в отчёте.

JSON результата служит признаком завершения, а не фиксированный `Sleep`. При сбое CPU-теста программа пытается выполнить GPU-тест только после подтверждённой остановки первого. Старый результат никогда не используется как результат второго запуска.

## Отчёты и backup

По умолчанию результаты находятся в:

```text
%LOCALAPPDATA%/WukongBench/reports/<дата-время-идентификатор>/
  report.json
  report.txt
  run.log
  installation-before.json
  installation-after.json
  cpu/ и gpu/
    result.raw.json
    result-source.txt
    requested-GameUserSettings.ini
    requested-Engine.ini
    after-run-GameUserSettings.ini
    last-screen.png
    last-screen.txt
```

Некоторые диагностические файлы появляются только при достижении соответствующего этапа. В консоль выводится тот же человекочитаемый отчёт. Ошибочные и частично выполненные сессии также получают отчёт; отсутствующий результат обозначается `null` в JSON и `N/A` в TXT.

Backup и журнал хранятся отдельно в `%LOCALAPPDATA%/WukongBench/state/<идентификатор-установки>/`. Перед первой модификацией сохраняются оригинальные байты всех файлов в двух возможных каталогах `Saved/Config/Windows` (в установке и в `%LOCALAPPDATA%/b1`), атрибуты и время изменения. Копии проверяются SHA-256. Восстановление удаляет новые конфигурационные файлы и возвращает оригиналы; пустые созданные каталоги могут остаться. Результаты и логи приложения не удаляются. Завершённые backup остаются в `backups/` для ручного восстановления.

При принудительном завершении утилиты, отключении питания или остановке ОС выполнить `finally` невозможно. Журнал сохраняется: следующий запуск восстанавливает конфиг перед новыми тестами. Если Benchmark Tool остался работать, сначала закройте его, затем выполните `--recover-only`. Если проверка контрольной суммы backup не пройдёт, автоматическая перезапись прекращается. При ошибке восстановления код выхода — `2`; журнал не удаляется.

## Известные ограничения

- Нет опубликованного стабильного API Game Science для автоматизации; адаптеры INI, JSON и текстовых кнопок основаны на исследовании доступных интеграций и требуют проверки на целевой установке. После обновления приложения они могут потребовать изменений. Программа не объявляет неподтверждённый запуск успешным.
- Неизвестный диалог (соглашение, выбор языка, предупреждение VRAM, Steam/DRM, shader compilation) не обходится случайным нажатием Enter. Сохраняется последний экран, затем срабатывает тайм-аут. Часть таких состояний может потребовать доработки `BenchmarkUiDriver`.
- HDR, оверлеи, нестандартный UI и перекрытые окна могут мешать OCR. Рекомендуется обычный SDR рабочий стол. Программа не меняет настройки Windows/драйвера, план питания, приоритет процесса или аппаратные лимиты FPS.
- Одновременные существующие конфиги в установке и LocalAppData считаются неоднозначностью и приводят к ошибке, чтобы не выбрать файл полной игры наугад. Нельзя параллельно запускать полную игру или редактировать конфиги: восстановление вернёт снимок начала сессии.
- Выбор адаптера через аргументы Unreal нуждается в проверке на ноутбуках с гибридной графикой. `GPUModel` и остальные исходные поля сохранены в `Results.ReportedSettings`; список DXGI-адаптеров и запрошенный индекс есть в Hardware.
- Утилита не измеряет производительность внешним сборщиком кадров и не вычисляет альтернативные FPS. Если история отсутствует или её схема изменилась, тест заканчивается ошибкой, а не вымышленным числом.

## Структура

```text
src/WukongBench.Core/          модели, VDF/INI, backup, parser и watcher истории
src/WukongBench/Program.cs     последовательность этапов, отмена и восстановление
src/WukongBench/Services/      SteamLocator, BenchmarkConfigManager, BenchmarkRunner,
                              BenchmarkUiDriver, BenchmarkProcessSession,
                              HardwareInfoProvider, ReportWriter, диагностика
src/WukongBench/Interop/       Win32 input, DXGI и D3D12
tests/WukongBench.Tests/       проверки независимой от Windows логики
docs/RESEARCH.md               источники, предположения, план проверки на Windows
```
